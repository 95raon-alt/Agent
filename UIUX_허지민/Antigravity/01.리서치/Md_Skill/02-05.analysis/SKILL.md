# 분석 단계 워크플로우 가이드 (Analysis Workflow Guide)

이 문서는 분류가 승인된 리서치 레퍼런스 자료를 바탕으로 홈페이지 UI/UX를 상세 분석하기 위한 가이드라인입니다. 에이전트는 아래의 단계별 지침에 따라 분석을 수행하고 결과를 생성해야 합니다.

## 1. 사전 확인 (승인 게이트)
- 리서치 및 분류 매핑 작업이 정상적으로 완료되고 승인되었는지 확인합니다.
- 분석할 대상 데이터가 준비되어 있지 않은 경우, 사용자에게 필요한 사항을 알리고 작업을 즉시 중단합니다.

## 2. 데이터 분석 기준
분류 승인된 데이터를 바탕으로 아래 기준에 따라 파싱 및 상세 분석을 수행합니다.
- **7대 분석 항목 적용**: 기본 정보, 디자인 스타일, 화면 구성과 레이아웃, 메뉴와 사용자 흐름, 문구와 콘텐츠, 주요 기능, 평가.
- **용어 규칙**: 전체 자료 비교 시 사용자 오해 방지를 위해 '반복 화면 구성'이라는 명칭 대신 `공통 레이아웃 패턴 (자주 사용되는 화면 레이아웃)`을 사용합니다.

## 3. Output Rules & Constraints (출력 제약 조건)
분석 완료 후 결과물 생성 시 다음 규칙을 엄격히 준수합니다.
- **원본 보호**: 기존 원본 리서치 및 분류 파일을 절대 수정하거나 덮어쓰지 않습니다.
- **파일 포맷 및 경로**: 분석 결과는 `output/` 폴더에 **UTF-8 인코딩 `.txt` 파일**로 생성합니다.
- **분할 규칙**: 1개 텍스트 파일 당 **최대 100개의 홈페이지**로 제한하여 분할 생성합니다 (예: `01_홈페이지별_분석_001-100.txt`, `01_홈페이지별_분석_101-200.txt`).
- **무단절 보존 원칙**: 한 홈페이지의 분석 내용은 절대로 두 파일로 쪼개어 나누지 않으며, 경계에 걸칠 경우 통째로 다음 파일로 이관합니다.

## 4. 분석 결과 검증
파일 생성이 완료되면 아래 항목들을 반드시 확인하고 사용자에게 보고합니다.
- 파일이 `output/` 폴더에 존재하며 크기가 0보다 큰지 확인.
- UTF-8 인코딩의 `.txt` 파일 포맷이 정확히 적용되었는지 확인.
- 파일당 100개 이하 제한 및 분할 규칙 준수 여부 확인.
- 한 홈페이지의 내용이 두 파일로 나뉘는 단절 오류가 없는지 점검.
- 7대 분석 항목이 누락 없이 모두 포함되었는지 점검.
- 수행하지 못한 검증이 있다면 명확히 보고하며, 검증 통과 시 생성된 파일 목록, 총 분석된 홈페이지 수, 검증 결과를 요약하여 보고하고 작업을 완료합니다.
